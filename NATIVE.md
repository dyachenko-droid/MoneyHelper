# Денежный помощник — нативная ветка

Контрольный коммит WebView: `08b9a0c` (`codex/webview`).

В этой ветке `MainActivity` сразу открывает `MoneyRoot`. Сохранены онбординг,
счета, операции и фильтры, бюджеты, цели, подписки, долги, аналитика, сканер чеков,
OCR, импорт выписки, экспорт и резервные копии, PIN/биометрия, виджеты и местные
напоминания через WorkManager. Hilt, репозитории, Room и DataStore сохранены.

Удалены WebView, удалённые сценарии запуска (`data/domain/presentation/launch`),
AppsFlyer/Install Referrer, Firebase Realtime Database/OneSignal и их конфигурация.
`MoneyApp` по-прежнему запускает `AppInitializer`: виджеты и напоминания работают
без зависимости от удалённого старта. Как в исходной нативной версии, разрешение интернета исключено из итогового
манифеста; разрешение уведомлений запрашивается на экране напоминаний.
Правило ProGuard для ComponentRegistrar сохранено: оно принадлежало исходному
сканеру ML Kit и требуется независимо от удалённой Realtime Database.

## Работа с ветками

- `codex/webview` — сохранённая рабочая версия с WebView и интеграциями.
- `codex/native-only` — нативная версия без удалённой маршрутизации.
- Исходная папка проекта остаётся на `codex/webview`; соседняя папка с суффиксом
  `-native` открыта на `codex/native-only` через Git worktree.
- В `outputs/git-backups` лежат проверенные `*.bundle` с контрольными коммитами.
- Обе ветки сохранены отдельно; релиз нативной версии запускается с `codex/native-only`.

Для возврата к WebView достаточно открыть исходную папку проекта. Переключать
ветки в занятом worktree не требуется. Нативные улучшения можно позднее перенести
отдельными коммитами через `git cherry-pick`; коммит удаления WebView переносить
в ветку WebView не следует.

Идентификатор пакета и формат локальных данных сохранены. Установка нативного
APK поверх прежнего с той же подписью сохраняет данные. Не удаляйте приложение
и не используйте `pm clear` для переключения вариантов. Старый SharedPreferences
`startup` нативной версией не читается и не изменяется: при возврате WebView
сохранённый адрес и признак первого запуска продолжают работать по прежним правилам.

## Проверки и сборка

```sh
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Тесты удалённого запуска находятся в ветке `codex/webview`; в нативной ветке их
исходники удалены вместе с соответствующей реализацией. Нативные проверки запуска
дополняются проверкой APK на эмуляторе. Это не подтверждает все игровые сценарии,
работу камеры на реальном устройстве или доставку локальных напоминаний.

## Улучшения в 1.1.0 (2)

1. Поиск включает категории частей операции, товары чека, заметку и оба счёта
   перевода. «Показать все операции» очищает поиск, месяц и остальные фильтры.
2. Над списком — итоги именно видимой выборки: количество, расходы, доходы и
   отдельная сумма переводов. При выборе счёта показаны входящие/исходящие переводы;
   дневной итог и изменение баланса учитывают направление. Перевод самому себе
   не изменяет баланс.
3. CSV: UTF-8/Windows-1251, ручной выбор кодировки и разделителя, кавычки,
   многострочный текст, строгие даты, точная десятичная арифметика до двух знаков.
   Отчёт считает все отклонения по причинам и показывает первые примеры строк.
   Совпадения проверяются внутри файла и на выбранном счёте; их пропуск можно
   отключить для разных покупок с одинаковыми датой, суммой и названием.
   Вставка всей выписки выполняется одной транзакцией. Максимальный CSV — 10 МБ.
   Восстановление CSV не равно полной копии: импорт пишет на выбранный счёт;
   переводы по умолчанию пропускаются, при отключении учитываются по знаку выписки.
4. Резервные копии: индикатор работы, защита от повторного нажатия, время последней
   успешной копии, ошибки без ложного сообщения об успехе. Новый `.backup` — ZIP
   со снимком SQLite и доступными фотографиями чеков. Снимок согласован транзакцией.
   Старые SQLite-копии версий 1/2 читаются после полной проверки целостности,
   структуры, типов, значений и связей. До подтверждения показана сводка, текущие
   данные не изменяются. Восстановление записей происходит одной транзакцией в
   работающей Room, без закрытия/подмены файла базы и перезапуска процесса.
   Перед заменой сохраняется внутренняя копия для отката; сбой до/во время записи
   оставляет текущие данные. Фотографии копируются в новые файлы, прежние не удаляются.
   Максимальная копия — 128 МБ, до 200 тысяч записей и 5000 фотографий; большие
   копии отклоняются до изменения данных. PIN, оформление и напоминания остаются
   текущими. Для новой копии проверяется совпадение валюты; старая копия без
   метаданных использует валюту текущих настроек. CSV сохраняет знак расходов < 1.
5. Карточка бюджета показывает регулярные платежи до конца месяца, остаток после
   них и доступную сумму на день. Учитываются все оставшиеся даты, в том числе
   несколько еженедельных платежей. Уже проведённый платёж сопоставляется по дате,
   счёту, сумме и названию, один к одному; он входит в расходы и повторно не
   резервируется. Это сопоставление по данным, поскольку старая схема не содержит
   идентификатора регулярного платежа в операции. Без лимита дневная сумма не
   показывается; при перерасходе она равна нулю, последний день считается одним днём.

Идентификатор пакета `ru.denpom.finance.app`, Room schema version 2 и DataStore
сохранены. Ветка WebView не меняется. В настройках отображается версия приложения.

## Автоматические проверки

Проверено локально: 40 JVM-тестов, 12 Android instrumentation-тестов (API 34),
`lintDebug` — без ошибок.

- JVM: поиск и сочетания фильтров, переводы, бюджет, CSV, повторный импорт и счета.
- Android instrumentation: отдельная Room в памяти, полный цикл всех 14 таблиц,
  старый формат, фото, предпросмотр/отмена, восстановление/откат, повреждённый файл,
  чужая валюта/тип, сбой записи копии, откат SQL после удаления и атомарность CSV.
  `IsolatedTestRunner` использует обычный Application без фоновых инициализаторов.
- Lint включён. В поставленной связке Kotlin 2.4 / lint 32.2.1 проверка
  `BidiSpoofing` зацикливается в `KotlinUFile.getAllCommentsInFile` (подтверждено
  повторными thread dumps). Она заменена `python3 scripts/check-bidi.py`, который
  проверяет исходники на невидимые управляющие символы направления; он запускается
  также в GitHub Actions. Остальные проверки не отключены.

```sh
python3 scripts/check-bidi.py
JAVA_HOME='/Applications/Android Studio.app/Contents/jbr/Contents/Home' ./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
# На эмуляторе, только изолированные тесты:
adb shell am instrument -w ru.denpom.finance.app.test/ru.denpom.finance.app.IsolatedTestRunner
```

## Подписанный релиз через GitHub Actions

`.github/workflows/release.yml` запускается вручную для `codex/native-only`.
Проверки JVM/Lint и сборка APK/AAB выполняются в GitHub. Ключ восстанавливается
из repository secrets `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`,
`KEY_PASSWORD` и удаляется после сборки. Ключ и JSON с паролем в Git не добавляются.
Артефакт workflow — `release-binaries`. После скачивания проверяются версия,
подпись APK/AAB и совпадение SHA-256 сертификата с предоставленным ключом.
