# Денежный помощник — запуск и интеграции

Пакет: `ru.denpom.finance.app`.
Firebase-проект: `ru-denpom-finance-app`.
Realtime Database: `https://ru-denpom-finance-app-default-rtdb.europe-west1.firebasedatabase.app`.
Настройки SDK находятся в `data/launch/IntegrationConfig.kt`; Firebase настроен
предоставленным `app/google-services.json` для этого пакета.

## Архитектура

Реализация запуска разделена на слои с внедрением зависимостей через Hilt:

- `domain/launch`: модели, интерфейсы репозиториев и сценарии
  `ResolveAttributionUseCase`, `ResolveLaunchUseCase`, `AcceptPrivacyUseCase`,
  `SyncNotificationIdentityUseCase`, `RequestNotificationPermissionUseCase`,
  а также `PaidLinkComposer`. Этот слой не зависит от Android и SDK.
- `data/launch`: адаптеры AppsFlyer/Firebase/OneSignal, HTTP-клиент GCD,
  SharedPreferences и управление сессиями/сетью. `StartupIntegrations` запускается
  из существующего `MoneyApp.onCreate()`.
- `presentation/launch`: Hilt ViewModel со состояниями Loading/Ready и экраны
  загрузки/WebView. ViewModel получает сценарии через конструктор, не обращается
  к Application и не создаёт репозитории самостоятельно.
- `di/LaunchModule.kt`: связывает интерфейсы с реализациями и создаёт сценарии.

Существующая инициализация финансового приложения, Room, DataStore, виджетов,
сканера чеков и PIN/биометрии сохранена. Настройки запуска остаются в прежнем
SharedPreferences `startup` с теми же ключами; финансовые данные не очищаются.

## Атрибуция и ссылки

AppsFlyer 7.0.0 инициализируется один раз на процесс. Install Referrer 2.2
подключён отдельной библиотекой. Сессия отправляется при сигнале SessionReady
и проверенной доступности сети, в том числе после возвращения из фона.

Первый запуск ожидает атрибуцию до 15 секунд. `Non-organic` выбирает `in_org`.
После `Organic` выполняется ожидание 5 секунд и уточнение через AppsFlyer GCD.
Если ответа SDK нет к 10-й секунде, также выполняется GCD-запрос, с возможным
повтором через 3 секунды в пределах общего лимита. Ошибка/неизвестный callback
не обрывает ожидание. Если результат не получен за 15 секунд, выбирается `org`.
GCD сохраняет кампанию вместе со статусом; поздние органические данные не
подменяют выбранную неорганическую атрибуцию.

На чтение Firebase отводится ещё до 8 секунд. Любая непустая строка, даже `12ук`
или строка из пробелов, принимается как ссылка. Проверок формата, домена или
схемы нет. Схема не дописывается, пробелы не удаляются, строка не нормализуется.

Строка `org` сохраняется и передаётся в WebView как есть.
Только строка `in_org` дополняется параметрами:

- `app_id` = AppsFlyer UID (`getAppsFlyerUID`).
- Кампания делится по `_`: части становятся `sub_1`, `sub_2`, ... по порядку.
- Пустые части сохраняют позиции, включая начало и конец кампании.
- Если кампании нет или она пустая, добавляется только `app_id`.
- Значения новых параметров кодируются для query. Остальные параметры, часть
  адреса до query и fragment сохраняются. Старые `app_id`/`sub_N` заменяются.

Тестовый шаблон для `in_org`:

```text
https://example.com/?app_id={app_id}&sub_1={sub_1}&sub_2={sub_2}&sub_3={sub_3}
```

Пример для UID `af-123` и кампании `one_two_three`:
`https://example.com/?app_id=af-123&sub_1=one&sub_2=two&sub_3=three`.

Итоговая ссылка атомарно сохраняется с `first_launch=false`, `remote_privacy=true`.
Она открывается без кнопки принятия. Последующие запуски сразу открывают эту
строку без Firebase/ожидания атрибуции и без повторного добавления параметров.

При пустой строке, отсутствующем поле, значении другого типа, ошибке или таймауте
Firebase показывается стандартная privacy с кнопкой «Принять»:
`https://dyachenko-droid.github.io/MoneyHelper/privacy.html`.
Закрытие страницы без принятия не завершает первый запуск. Принятие сохраняет
`first_launch=false`, `remote_privacy=false` и открывает нативное приложение;
последующие запуски уже не показывают стандартную privacy. Удалённая ссылка,
совпадающая со стандартной, всё равно считается удалённой и не получает кнопку.

## OneSignal и WebView

В OneSignal передаётся `external_id`, равный AppsFlyer UID, через `OneSignal.login`.
Используется тот же UID, что помещается в `app_id`. Привязка действует для всех
типов установки и повторяется при готовности SDK, если UID ещё не был доступен.
Разрешение на уведомления запрашивается один раз в нативном приложении либо
удалённом WebView; при стандартной privacy — после принятия.

WebView поддерживает cookies, DOM storage, JavaScript, выбор одного/нескольких
файлов через системное окно и возврат по истории. Множественный результат
читается из ClipData, одиночный — из Intent.data. При отмене callback получает
null; при закрытии WebView незавершённый выбор отменяется. Резервный выбор файлов
работает через ACTION_OPEN_DOCUMENT.

Если истории нет, кнопка/жест «Назад» игнорируются: WebView не закрывает Activity.
Ошибка загрузки показывает повтор и не заменяет сохранённую ссылку стандартной.
HTTPS-сертификаты проверяются штатным WebView. Загрузка и WebView поддерживают
поворот через RotatingScreen, включая системную блокировку вращения. Отладочных
панелей, поля ссылки и диагностического журнала в этой сборке нет.

## Проверка

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

При обновлении APK используется ранее сохранённый адрес. Для теста нового
получения Firebase/подстановки параметров можно удалить только настройки
запуска, сохранив финансовую базу и остальные данные приложения:

```sh
adb shell am force-stop ru.denpom.finance.app
adb shell run-as ru.denpom.finance.app rm -f shared_prefs/startup.xml
```

Не используйте `pm clear` для этого теста: он удаляет и финансовые данные.
Debug APK работает без release-keystore. Release-подпись применяется при наличии
всех полей `keystore.properties`. Реальная рекламная установка проверяется на
тестовом устройстве через AppsFlyer; доставку push настраивают в OneSignal.
Тестовые push-сообщения автоматически не отправляются.
